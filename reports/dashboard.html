The data and its traps

IBM's synthetic HI-Small: 10 days of normal traffic, then 8 sparse "tail" days (1,108 transfers, 59% of them laundering, completing earlier attempts). The split follows IBM Multi-GNN's day boundaries.

The causal feature engine

One incremental engine computes 79 candidate features (75 pass the drift gate and feed the model) and the 7 rule severities, minute by minute, from state as of the previous minute. The same code will score the live stream.

Graph neural network (Multi-GINe)

The GNN reads each transfer's neighbourhood in the money network, sampled only from strictly earlier minutes. A look-ahead twin sees the whole period, as the published HI-Small pipelines do; the gap between the two is what peeking at the future is worth. Test results first, then training.

Live streaming

Kafka feeds a FastAPI scorer that keeps the causal graph state and serves LightGBM-graph. One Docker Compose run replays 100,000 test transfers at rising rates; every score is checked against the offline model as it streams.

Case packs

Every alert gets an evidence pack for an analyst: who, what, when, where, why (score, top model drivers, rule hits, a typology guess) and how (the money-flow subgraph from the 3 days before, nothing later). In the demo each one is a page at /cases/<id>.

Compute cost

Every heavy stage runs on Modal (GPU only for GNN training). Budgets were set before the work; the GNN runs passed a cost gate before each submission.
